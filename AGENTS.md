# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- [VISION.md](VISION.md) is the project's acceptance policy, co-authored with the repo owner against 17 recorded hypothetical verdicts; check a proposed surface against its closing aligns/resisted tests before building it.
  It deliberately sits ahead of today's implementation in places: accuracy of the reported number is the first obligation, and boundaries such as read-only and never-launch hold as "least action that yields a true reading" rather than as absolutes.
  README Security Posture remains the description of what actually ships today; do not restate VISION.md wording as a current guarantee.
- quota-axi is data only.
- It reports local Claude, Codex, Cursor, GitHub Copilot, Grok, Kimi, Z.AI, Alibaba, OpenCode Go, Antigravity (`agy`), Command Code, MiniMax, MiMo, DeepSeek, OpenRouter, ElevenLabs, and Devin quota windows, and it must never route, recommend, rank a winner, order providers preferentially, proxy, intercept, log in, import browser cookies, or mint/rotate a credential.
- Delegated credential refresh is the one carve-out and it is shared machinery in `src/providers/delegated-refresh.ts`: a delegate is eligible only when the same stored access token is expired, carries a refresh token, and was definitively rejected; quota-axi may then run the vendor CLI's own smallest non-interactive rotation command and re-read the store that CLI rewrote. quota-axi must never perform a refresh-token exchange itself (these tokens rotate on use; a second exchange signs the user out of the harness being measured), and the delegated-refresh machinery must never read a refresh token's value - presence only.
  quota-axi also never signals a delegated run: the budget bounds only how long quota-axi waits, the child runs in its own process group (Ctrl+C on a live `--tui` must not reach it), and a run that outruns the budget resolves as `unconfirmed`/`refresh_timed_out` - reported as unmeasured or stale, never as a sign-out, and never retiring the cache.
  Claude adds a best-effort safety check on top: before delegating, `src/lib/running-processes.ts` must report no Claude Code process, because Claude Code owns that session's refresh. This also prevents a later read from stacking another refresh on a timed-out `claude doctor` that is still running. An unlistable process table stays read-only. The check and spawn are not atomic, so a Claude Code session starting after the check or another concurrent quota-axi read can still overlap the delegate. This narrows the common repeated five-minute `--tui` versus live-session collision and, together with never signaling the delegate, is strictly safer than force-killing without adding a failure mode beyond the pre-existing vendor-owned race. Tests mock that module so the machine's real process table never decides a test. Contract, per-provider delegates, and the read-only providers are documented in [README Delegated credential refresh](README.md#delegated-credential-refresh); route any new provider's delegate through that module rather than spawning ad hoc.
- A provider gets a delegate only when that command's rotation behavior is established empirically from the vendor's own CLI. Today: Claude `claude doctor`, Grok `grok models`, and Codex's existing `app-server` probe. Cursor, Copilot, Kimi, Z.AI, Alibaba, OpenCode Go, Antigravity, Command Code, MiniMax, MiMo, DeepSeek, OpenRouter, ElevenLabs, Devin, and Pi-owned entries stay read-only; leaving a provider read-only is always allowed, forcing an unsafe or interactive path never is.
- Data-only reconciliation: quota-axi does publish one derived per-scope comparative selection signal (`effectiveAvailability[].selection`), computed purely from figures it already reports. That is data, not routing - the consumer does any routing or ranking. Keep this distinction in `src/skill.ts` frontmatter/identity wording and README wording; never claim quota-axi recommends or ranks.
- The shipped skill stays MINIMAL and DEFERS to the CLI for all actual guidance. `src/skill.ts` generates `skills/quota-axi/SKILL.md` as a stub: identity/discovery frontmatter, what quota-axi is, when to reach for it, and pointers to `npx -y quota-axi` (default TOON), `--help`, and `--json` / `--full`. quota-axi CLI output is the single source of truth; never re-duplicate CLI-owned instructions into the skill. Prefer a pointer over restated detail.

- An inherited bound is only as good as the evidence that the vendor enforces it. `availability()` in `src/interpretation.ts` takes an optional own-windows argument; when every window metered for a scope alone still reports allowance while an inherited window reads zero, it publishes `effectiveAvailability[].boundConflict` and leaves the scope `unknown` instead of asserting `exhausted_now`/`effective 0`. That is disclosure, not the opposite assertion: one successful call proves the inherited bound was unenforced at that moment, not that it never binds. - OpenCode Go's rolling, weekly, and monthly windows are stacked plan caps that jointly bind Go-plan usage at `all_models` scope (`opencodeGoSemantics` in `src/interpretation.ts`, following the Kimi/Z.AI partial pattern for unfamiliar windows). The joint-bound evidence is the vendor's own Go docs: $12 per rolling 5 hours, $30 per week, $60 per month, with plan requests blocked at a zeroed cap. When the usage endpoint carries no duration of its own, `src/providers/opencode-go.ts` `normalizeWindow` falls back to those plan-declared cycle lengths (rolling 18,000 s, weekly 604,800 s, monthly a derived `startsAt` one calendar month before the reported `resetsAt`, day clamped); a payload duration wins, and only a payload-supplied 18,000 s rolling duration promotes the `rolling` window to `five_hour`. It reports no Zen balance, so a zeroed plan window with an opted-in balance fallback still reads plan-exhausted with the fallback named only in prose. Contract in [README Quota windows](README.md#quota-windows).
- Kimi `/usages` accepts the current `usages` map (`limit_5h`, `limit_7d`, `limit_month_total`, `limit_month_code` with `used_ratio`) and the legacy `usage` plus optional `limits[]` path. Absent map entries stay absent, the ratio is read from `used_ratio` only, and neither shape invents a monthly duration.
  `month_total` alone gets a `startsAt` one calendar month before its reported reset (none without a reset), because Kimi documents that total as the membership's monthly quota refreshed on the subscription date; the cited evidence is in [README Quota windows](README.md#quota-windows). Every renewal-dated cycle (Cursor, OpenCode Go, ElevenLabs, Kimi) steps back through the one `calendarMonthsBefore` in `src/lib/time.ts`.
  `limit_month_code` is the code-typed share of `limit_month_total` as the vendor serves it (kimi-code's `usage-format.ts` derives its `kimi` row as `monthTotal - monthCode`), not a separate cap, so `month_code` stays a distinct window carrying only `percentUsed` plus `shareOf: month_total`, and `kimiSemantics` recognizes it without ever bounding a scope with it - deriving a `code` remaining would claim more headroom than the account has.
  Default TOON names that used-share as an `attention[]` `share` row; `--tui` prints `percentUsed` of the parent instead of a remaining bar or `?`.
  The `shareOf` marker on the window is the single share rule everywhere - interpretation, TOON, TUI, and the `--json` tier split, which keeps `percentUsed` for a share window because it is that window's only figure; never reintroduce a window-id special case, and never derive a remaining from a share.
  A snapshot cached before the marker existed is upgraded on read so a stale Kimi fallback is not rendered as missing data ([README Cache](README.md#cache)).
  A declared map entry that carries no usable ratio is named `usages:<key>` in `state.untrustedWindowIds` so the account bound reads `partial` instead of settling on the entries that did parse, and an unrecognized map key is ignored rather than promoted to a window. Contract in [README Provider windows](README.md#provider-windows) and [README Quota windows](README.md#quota-windows).
  A body that declares no quota-bearing field at all - `usages` absent/null/`{}`, `usage` absent/null, `limits` absent/null/`[]`, no key besides the vendor's own `goods_version`/`boosterWallet` - is a live, authenticated Free-tier account's established-empty `/usages` reading (the vendor's own client renders it "No usage data available"), not `schema_invalid`. `normalizeKimiPayload` reports that case as `{ kind: "no_quota" }` distinct from `{ kind: "windows", ... }`, `readKimiQuota` maps it to `selectCredential`'s `live_no_quota` outcome, and the per-source loop in `acquireKimiQuota` carries that floor across Kimi's two sources the way Grok does, so the sibling Kimi Code CLI source is still consulted. If no source yields windows but one proved live, the provider reports fresh with `windows: []` and `authStatus: "usable"` instead of an error, which - per [README Cache](README.md#cache) "fresh with no windows" - clears rather than preserves that context's cache slot. A body that declares a quota field this reader cannot parse (a non-object root, a `usages` entry missing `used_ratio`, a legacy `usage` object with no usable `limit`, or unknown-only keys) still fails as `schema_invalid`.

- GitHub Copilot reads the stores in `COPILOT_SOURCE_ORDER` (`src/providers/copilot.ts`): `$GITHUB_COPILOT_APPS_JSON` or the local `github-copilot/apps.json` first, unchanged when it works and still named `api` when its token is fetched, then the standalone Copilot CLI sign-in's native secure-store item (`copilot-cli:keychain`, `src/providers/copilot-cli-credential.ts`; macOS Keychain or Windows Credential Manager through the bounded `CredReadW` transport in `src/lib/windows-credential.ts`), then the GitHub CLI login's `hosts.yml` (`gh:hosts.yml`, `src/providers/gh-cli-credential.ts`), because current Copilot sign-ins no longer write `apps.json`. - Multi-source providers report the source that works: a broken store must never speak for a provider whose sibling store still answers. Sources are consulted in priority order and handover happens on credential problems only, never on transport/decoding/server failures (those belong to the request, not the credential). The superseded source stays visible: `src/lib/source-attempts.ts` classifies attempts (`status: "failed"`, or `skipped` with `credentialPresent`; a provider sets `degraded: false` on a non-credential attempt such as Grok's live model probe or Claude's `oauth-profile`), `withQuotaSemantics` in `src/interpretation.ts` publishes `state.degradedSources` on fresh readings only, and `src/render.ts` emits the `degraded_source` attention row. Contract in [README Default report blocks](README.md#default-report-blocks) and [README Provider `state`](README.md#provider-state).
- Credential selection is shared machinery in `src/providers/credential-selection.ts`: stored expiry is advisory only within one source, never a verdict or a reason to reorder declared sources. Stored-expired credentials are empirically tested in that source's fixed position before any expired/sign-in verdict, an empirically live credential always wins, and transient failures never switch candidates within one source or become auth verdicts. Independent Grok CLI and Pi sources may still be tried in turn. New or migrated provider adapters must route multi-credential selection through this module instead of skipping expired-by-stored-field credentials; Claude's advisory-expiry loop is the semantic precedent. Grok, Codex, Kimi, Copilot, and OpenCode Go route through it; Codex, Kimi, and Copilot call it once per source so each provider's ownership-stability order stays authoritative. A broker's `expired` resolution therefore carries the stored token (probe use only, never logged or rendered) so the adapter can test it.
- Provider and credential-source onboarding checklist:
  1. Enumerate every source in an ownership-stability order declared by a named constant. Keep `absent`, `structurally_invalid`, `unsupported`, `read_error`, and `resolved` (stored-valid or stored-expired) distinct at the typed local-resolution boundary; route Pi entries through `classifyPiAuthEntry` in `src/lib/pi-auth-store.ts`, and derive `credentialPresent` once from that resolution rather than at each call site.
  2. Separate local resolution from the bounded read-only liveness probe. Enroll stored-expired credentials instead of skipping them, never infer liveness from presence, and classify probe outcomes as `usable`, `live_no_quota`, `definitively_rejected`, or `transient`; only a first-party 401/403 is an auth verdict.
  3. Handover only after definitive credential failure. An absent source is never degraded; a present-but-broken source superseded by a working sibling is degraded on fresh readings only; stale means last-known cache. Inspect refresh-token presence only, and never read or exchange its value.
  4. Add adapter regressions for primary healthy, stored-expired plus live sibling, structurally invalid present, absent source, all rejected, refreshable expired, and transient stops handover; extend the cross-provider invariant table in `test/credential-contract.test.ts`.

- Kimi's credential, fallback, and transport contracts are documented in [README Security Posture](README.md#security-posture). Kimi Code stores one credential per environment and both halves of that environment must travel together: `src/providers/kimi-code-config.ts` reads the OAuth reference `config.toml` persists (`storage`, `key`, `oauth_host`, plus the provider's `base_url`) and returns the slot file name with the base URL its token was issued for, so no reading can pair one deployment's token with another's host. Its region allowlist is Kimi Code's own two published deployments; an unrecognized pair sends no request rather than trusting a configured origin. The reader is deliberately narrow rather than a TOML dependency because `api_key` sits in the very table it reads - keep the key whitelist tight, and prefer following Kimi's persisted pointer over recomputing its slot hash. A configuration that exists and could not be walked to its reference is `environment_unconfirmed`: it may name any slot, so quota-axi opens no credential there at all, because nothing found at a guessed location describes the current account in either direction - not its absence or expiry as a sign-out, and not its contents as this account's quota. An assumed environment also carries its own cache identity, distinct from the confirmed environment that names the same slot and host, so a mainland snapshot is withheld from - never retired by - a global login whose configuration went unreadable. An absent `config.toml`, and one walked to its end that names no OAuth reference, both keep the full default reading. Pi's `kimi-coding` entry is read in place as either an `api_key` or an `oauth` access token; absent files or entries resolve as `missing`, malformed stores or entries as `invalid`, unknown types as `unsupported`, and expired OAuth as `expired`, which carries the stored token so it is probed in Pi's fixed source position before falling through to the Kimi Code CLI source. It is never refreshed, mirroring `src/providers/pi-xai-credential.ts`. A definitively rejected, stored-expired credential with a refresh path becomes a non-definitive `expired_refreshable` failure: if it defines the provider report, `state.status` is `unavailable` and the Kimi cache is preserved, never `auth_required`. The Pi broker reports `refreshable` from `refresh`-property presence, `src/providers/kimi-code-cli-credential.ts` mirrors it with `Object.hasOwn(credential, "refresh_token")`, and `src/providers/kimi.ts` maps such a probe outcome through `refreshableExpiryFailure`. The refresh token's value is never read or exchanged anywhere on this path - presence only, rotation stays the vendor CLI's. All Pi auth readers route their provider-entry boundary through `src/lib/pi-auth-store.ts`, so only an absent file or provider property is `missing`; a present non-object entry is `invalid`.

Claude, Codex, Copilot, Cursor, Grok, Z.AI, Command Code, MiniMax, DeepSeek, OpenRouter, ElevenLabs, and Devin route their remote HTTP calls through `src/lib/http.ts` so standard upper/lowercase HTTP(S) proxy and `NO_PROXY` environment policy is applied consistently without logging proxy URLs; route new remote fetches through it rather than global `fetch`. The proxy path pairs the installed `undici` build's `ProxyAgent` with that same build's `fetch`, because Node's global fetch only accepts a dispatcher from the undici build Node bundles and Node 26 rejects the npm `ProxyAgent` with `InvalidArgumentError: invalid onError method`.
- `ProviderOptions.refreshCredentials` gates delegated refresh. `--no-credential-refresh` turns it off; the read-only `auth` command always passes `false`. Tests must pass it explicitly so no test can spawn a vendor CLI by accident.
- `--profile-only` is the fail-closed single-account quota probe for Claude and Codex: it requires `CLAUDE_CONFIG_DIR` or `CODEX_HOME`, reads only that profile's native credential file, and bypasses alternate sources, delegated refresh, and quota cache access. Full JSON keeps non-secret account/source/attempt evidence; ordinary output stays redacted. Contract in [README Profile-only quota reads](README.md#profile-only-quota-reads). Omitting the flag must preserve legacy discovery and cache behavior.
- Slow-path CLI plumbing (routing, `--help`, trailing version flags, error framing, exit codes, and the built-in `update` self-updater) comes from `axi-sdk-js` `runAxiCli`, matching sibling tasks-axi; machine TOON/JSON rendering stays in `src/render.ts` and the command bodies live in `src/commands.ts`.
- `bin/quota-axi.ts` answers a bare `-v`/`-V`/`--version` through `axi-sdk-js/fast-path` plus the leaf `src/version.ts` (node builtins only), and imports `src/cli.js` dynamically so the provider graph never loads on that path. Keep `src/version.ts` leaf-clean; `test/version-fast-path.test.ts` guards this with an ESM loader module trace (plus negative control) and flag parity, deliberately with no wall-clock CI assertion.
- `quota` is the implicit default command: `runAxiCli` routes on `argv[0]` and rejects a leading flag, so `src/cli.ts` `normalizeArgv` prepends `quota` for a bare call or flag-first call (`quota-axi --json`) while leaving `auth`, `update`, single-token `--help`, and any version flag that reaches the slow path to the SDK. Validation errors throw `AxiError("...", "VALIDATION_ERROR")` (exit 2); the all-providers-failed path sets `process.exitCode = 1` and still renders.
- Default stdout is compact TOON, restructured into three decision-shaped blocks: `quota[]` (one fully populated row per measurable scope), sparse `exhaustion[]` (finite-runway measurable scopes only, joined on `provider` + `scope`), and sparse `attention[]` (every non-nominal fact). Its visibility and order invariants are documented in [README Default report blocks](README.md#default-report-blocks) and covered by `test/cli.test.ts`. `spendPriority` renders the literal `unknown`, never `0`; an unknown or stale scope gets no `quota[]` row, and any finite-runway verdict for it is preserved in `attention[]` with the limiting window. Provider attention details preserve `state.reason`.
- `--json` emits the normalized model with derivation inputs demoted to `--full`, with no renames and no re-nesting; `--full` also adds account identity and per-source attempts. The tier split, including absence markers, is documented in [README Output tiers](README.md#output-tiers). **Demote at the renderer/serialiser only, never at computation**: `src/render.ts` `quotaJsonReport` builds the `--json` payload, `renderQuotaToon` builds TOON, and the in-memory model keeps every field so `--tui` and `--full` are unaffected. Presence for both the marker and the TOON omission is classified in `quotaCommand` before redaction.
- There is deliberately no `projectionBasis` field anywhere: every projection is cycle-average, and its absence means `cycle_average`. There is no `selection[]` TOON block either - the scalar is already the `quota[]` row's `spendPriority` column.
- `--tui` (quota command only, mutually exclusive with `--json`) renders the human card-grid report from the pure renderer in `src/tui.ts`, driven on an interactive terminal by the injected-io live loop in `src/tui-live.ts` (`--refresh`, `--once`, `q`/Ctrl+C to quit); it is presentation only, documented in [README Human terminal report](README.md#human-terminal-report---tui), and must never change the TOON/JSON machine contract, exit codes, or caching.
  Its live / stale / needs-attention / not-set-up tiers come from `providerPresence` in `src/lib/source-attempts.ts`, which reads source attempts; a stale cached reading is its own tier and is not counted live. Redaction strips those attempts, so `src/commands.ts` classifies the complete model and passes `presence` to the renderer. Fold only on positive evidence of absence (every attempt skipped with no credential present and no degraded store, never keyed on error wording in the classifier), and declare exceptions on the adapter that owns the source instead of special-casing them in the TUI: `isUncertainSkip(attempt)` for skips that establish nothing either way (Copilot's unconfirmable CLI account, unsupported secure store, and account whose secure-store value still awaits `--allow-keychain-prompt`; Kimi's `environment_unconfirmed` configuration, which names no slot in either direction; every Antigravity skip except its two exported true-absence errors, so an installed CLI that timed out or a discovered endpoint that failed keeps `agy` in view), and `incidentalSources` for a sibling tool's login (Copilot's gh fallback, where only a readable-store skip or a definitive refusal is not evidence of use - an unreadable `gh` store or a transient request failure keeps Copilot in view).
- `renderQuotaTui` is deliberately height-independent: it lays cards out for the width and returns however many lines that takes. The alternate screen has no scrollback, so the live loop must never paint more physical rows than the terminal has - `src/tui-viewport.ts` `scrollFrame` windows the frame using terminal display widths, pins the first line, clips oversized lines, and reserves the last row for the scroll affordance when height permits; content wins those rows in tinier terminals. `src/tui-live.ts` owns the offset and scroll keys. Keep the closing hint out of `renderQuotaTui` (compose it with `renderTuiHintLine` + `scrollHint`), and keep the live paint free of a trailing newline so a frame that exactly fills the terminal does not scroll itself.
- Keep the `--tui` direction preference on the human rendering path in `src/commands.ts` and `src/tui.ts`; never let it change the model or machine output. `test/tui-show-agent-output.test.ts` guards this boundary. User-facing settings and display behavior are owned by [README Human terminal report](README.md#human-terminal-report---tui).
- TUI wording is humanized independently of the machine contract: `through_reset` renders as `on pace ✓`, pace is shown only by the bar fill and `┃` marker (no burn-multiple chip or legend), and projected exhaustion is a relative `empty in Nd Nh` headline countdown (no triangle prefix, warning styling retained) with no absolute-time body note. JSON and TOON keep `through_reset`; the complete `pace` object remains in the in-memory model and `--full --json`. The headline bar uses the binding window's own label from `limitingWindowIds` (`week`/`session`/`credits`) as its primary label; scoped rollups may append their model or product scope. A provider with wholly unknown window relationships drops the headline percent, verdict, and bar for a single `per-window usage · no combined bound` line instead of rendering an empty track. See [README Human terminal report](README.md#human-terminal-report---tui).
- JSON report shape and quota interpretation, including stale effective availability, per-window cycle-average pace, effective usable runway, and the per-scope selection signal (`schemaVersion: 5`, or `6` when a provider expands to multiple accounts), are documented in [README Output Model](README.md#output-model), [README Pace signals](README.md#pace-signals), [README Effective usable runway](README.md#effective-usable-runway), and [README Per-scope selection signal](README.md#per-scope-selection-signal). Pace, runway, and selection are derived in `src/pace.ts` from trusted `startsAt`/`resetsAt` or `windowSeconds` plus `generatedAt`; runway aggregates every authoritative bound, preserves uncertainty, and is not cached. Negative `reservePercentPoints` means usage is ahead of the reset clock. `state.retryAfter` can appear for provider rate limits, and `state.reason: keychain_access_required` plus `state.remedyCommand` can appear when a stale or unavailable Claude, Cursor, or Copilot result is blocked by a skipped secure-store read.
- `summarizeEffectiveSelection` in `src/pace.ts` is the selection scalar's only implementation, and `SELECTION_SCALAR_KEY` in `src/types.ts` is the single place its published field name is spelled. Any bounding window without usable pace makes the whole scope unmeasurable (no scalar, `unmeasurableWindowIds` named); an unknown window is never assumed healthy or defaulted to zero. `worstReservePercentPoints` stays the non-routing single-window diagnostic and must not be conflated with it.
- macOS Claude Keychain presence and value reads mirror Claude Code's validated current-user account selector and never fall back to an ambiguous service-only query. Value reads are skipped on plain calls until a successful value read records the service-and-account-scoped non-secret access marker under the quota-axi cache directory; after that, plain calls may reuse the existing grant and read live Claude quota. Claude exact profile/secure-storage selection, search-list discovery, and per-refresh item replacement are documented in [README Provider notes](README.md#provider-notes); opaque-default selection requires complete, conclusive search-list metadata, and absence additionally requires no matching or unfamiliar Claude item, and every Keychain failure (including exit 44) must not retire the Claude cache. Offer `--allow-keychain-prompt` only for `keychain_prompt_required`; denied/timeout Keychain outcomes must still appear as errors. A stale usage-fetch failure names `fetch failed` plus the actual error in `attention[]`.
- Managed-profile, Claude identity, and Codex credential-source, refresh-ownership, and executable-override contracts are documented in [README Security Posture](README.md#security-posture).
- `--allow-keychain-prompt` is the first-time opt-in that permits Claude, Cursor CLI, or Copilot CLI Keychain value reads which can prompt, plus Windows Copilot CLI Credential Manager reads (no OS prompt promised), and agents should relay the one-time "Always Allow" grant when `keychain_access_required` advice appears.
- Codex uses `$CODEX_HOME/auth.json` or `~/.codex/auth.json` OAuth, then Pi's `openai-codex` entry and any already-present `openai-codex-*` siblings in the same Pi `auth.json`, before the CLI fallback. A higher-priority source's real failure is never overwritten by a lower-priority one's credential diagnostic. Distinct Pi siblings are independent account lanes collected through `src/providers/accounts.ts`, alongside a native `codex-home` lane (`auth.json`, then the CLI fallback) whenever `auth.json` exists or an installed CLI fallback yields a reading, a confirmed ChatGPT `account/read` login, or a cached `codex-home` snapshot (a native reading, from `auth.json` or the CLI, whose account id matches a Pi lane collapses into that lane, which then publishes whichever of the two readings is fresher and retires the `codex-home` snapshot); one account's failure or exhaustion must not hide or substitute another, and the same account - matched on the id a fresh reading reports, else the stored one, never on email, tokens, or key names - is never reported twice as extra capacity, so a Pi key repeating an account already claimed stays that lane's credential fallback. Contract in [README Multiple accounts](README.md#multiple-accounts).
- Codex `auth.json` support is OAuth-token only; never treat `OPENAI_API_KEY` as valid quota auth or send API keys to ChatGPT quota endpoints.
- Claude env-scope handling and the opt-in native inference contract are owned by [README Provider notes](README.md#provider-notes), implemented in `src/providers/claude-native-quota.ts`, and covered by `test/providers/claude-env-token.test.ts` and `test/providers/claude-native-quota.test.ts`. Keep that inference path separate from delegated credential refresh.
- The read-only Alibaba `bl` usage command and Codex app-server JSON-RPC probe are the CLI quota fallbacks; the Codex probe also doubles as Codex's delegated refresh.

A definitive sign-out retires that provider's snapshot through `staleUnlessSignOut` in `src/providers/common.ts` (`auth_required` with or without a cache). Transient failures and `expired_refreshable` keep the stale fallback. Contract in [README Cache](README.md#cache).
- The Claude Keychain access marker is stored alongside the cache, is `0600`, is keyed by the hashed selected service plus account, and contains no credential material or raw account/service name. Markers written by earlier versions are ignored without being deleted.
- Quota cache files must be `0600` and contain only normalized non-secret snapshots.
- [README Cache](README.md#cache) owns snapshot eligibility, exclusions, and per-account slot clearing. Context-scoped providers whose identity a reading always has (Claude, Kimi, Command Code, MiniMax, ElevenLabs, and Devin) skip both cache write and clear when the current reading has no context identity. Claude, Kimi, Command Code, MiniMax, ElevenLabs, and Devin snapshots additionally carry an opaque SHA-256 selected-configuration context identifier (Claude's profile and credential-storage selection, Kimi's home plus the slot and base URL its `config.toml` resolves to - never that file's bytes, which hold an `api_key`, Command Code's winning source plus the account identity `whoami` established, MiniMax's answering credential source plus deployment host, ElevenLabs' source plus a one-way digest of the answering key, and Devin's answering source, host, and a one-way digest of the session token), and stale fallback rejects legacy or mismatched contexts. Codex snapshots carry one too, hashed from the ChatGPT account id the one credential that produced the reading stored, because a Codex slot name never fixes the account: the keyless slot is shared by a lone discovered lane and the single-account path, and a stable Pi entry key can be signed in elsewhere. The vendor's response id is not the stamp - it can differ from the store while the same token is live, and a failed probe only has the store. `readCachedCodexProvider` therefore withholds a snapshot only on a proven mismatch against the credentials the failed reading actually tried - a sibling never probed does not vouch for it, and a transient probe failure is vouched for only by its own credential, while an unstamped snapshot, or a reading whose tried credentials name no account, proves nothing and is still served. Route any provider whose account a slot name cannot fix, or whose local configuration selects the account, through `CONTEXT_SCOPED_PROVIDERS` in `src/cache.ts` rather than adding a per-provider field. A context read from a file the vendor rewrites must not be re-derived at write time, and it must describe the source that actually answered: Kimi takes one `KimiCodeSelection` before it requests anything and publishes the answering source's identity through `src/providers/kimi-cache-context.ts` - that selection for a CLI reading, the Pi source and its fixed default endpoint for a Pi-brokered one. So a login switching deployments mid-run cannot file one environment's numbers under another's, and a Pi reading is never attributed to a deployment it never contacted.
- Fresh reuse is opt-in (`--max-age`, or `QUOTA_AXI_MAX_AGE` for a host; the flag wins) and serves a provider's last successful reading instead of asking the vendor, owned by `readReusableProviders` in `src/cache.ts` and called from `fetchQuota` in `src/commands.ts`; contract in [README Fresh reuse](README.md#fresh-reuse). Its identity is the hashed `CREDENTIAL_SELECTION_ENV` in `src/lib/reuse-context.ts` plus the state of every local file the reading opened, traced through `src/lib/input-trace.ts`. A new environment read must be listed there or declared non-selecting in `test/reuse-context.test.ts`, which reads every provider under a recording environment (a read reached only past a present credential file escapes it), and a new provider file read must go through the `src/lib/fs.ts` readers or call `traceInput`, or a changed login can be answered with the previous account's reading. quota-axi's own cache is read untraced, because every write changes it. `QUOTA_AXI_SNAPSHOT` is the fixture surface on the same path. With reuse enabled, concurrent cold reads single-flight per provider and credential selection through the lock in `src/lib/fetch-lock.ts`; the lock only saves vendor calls, so every served reading still passes the cache's reuse checks.
- Failed providers, stale providers, account identity, source attempts, and derived `pace` objects are not cached.
- Stale fallback serves only cached windows that can still be true: `servableStaleWindows` in `src/providers/common.ts` drops reset-expired windows and age-bounds resetless ones by declared duration or kind, and `staleFromCache` returns `undefined` when none survive so the caller reports its own failed read. Every stale path, raw or provider-specific, routes through it; ElevenLabs' `"never"` resetless policy, Claude's seven-day snapshot bound, and the shorter resetless bounds Claude and Kimi kept (five hours for resetless monthly windows) are the only documented exceptions: the shared rule adds bounds but never extends a provider's shorter one. Contract in the `Stale fallback bound` row of [README Cache](README.md#cache).
- Do not cache raw provider responses or credential headers.

## Release process

Releases are cut by release-please from conventional commit messages on `main`; merging the bot's release PR triggers `npm publish` via `.github/workflows/release-please.yml`, using npm's OIDC trusted-publisher flow (`id-token: write` + `--provenance`), not an `NPM_TOKEN` secret.
`.release-please-manifest.json` is primed at `0.1.0`, the version already published to npm by hand before release-please was wired up; release-please owns every version after that.
`release-please-config.json` intentionally sets `bootstrap-sha` to `9f5dc949c50ab8ac0a441be777e1c3693ee0b612`, the commit that produced the already-published npm `0.1.0`; do not retarget it to later scaffolding commits unless the published baseline itself is being corrected.
Do not hand-edit `CHANGELOG.md` or `.release-please-manifest.json` (a guard workflow blocks PRs that touch them), and regenerate `skills/quota-axi/SKILL.md` with `pnpm run build:skill` instead of editing it directly (`pnpm run build:skill -- --check` in CI fails if it drifts from `src/skill.ts`).
Every `pull_request` workflow must `paths-ignore` the release-please output set (`.release-please-manifest.json`, `CHANGELOG.md`, `package.json`), with exactly one deliberate exception: the workflow backing the no-mistakes gate check (see Contribution gate) must carry **no** path filter, because the gate's verdict is a function of the PR body rather than of the files it touches. `test/release-ci-exclusions.test.ts` derives the output set from `release-please-config.json`, identifies the gate structurally by its job name, and fails if either half drifts.

## Lockfile formatting

The committed `pnpm-lock.yaml` is Prettier-formatted, which is not pnpm's native output format.
After changing dependencies, run `pnpm exec prettier --write pnpm-lock.yaml` so the diff collapses to the real change instead of a wholesale reformat; CI's `pnpm install --frozen-lockfile` parses the YAML structurally and accepts this formatting.
